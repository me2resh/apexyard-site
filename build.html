Build

Your agents plan before they code, and every change meets a reviewer before it leaves your machine.

For founders and engineering leads who want agent speed without losing the process.

Install Build

Open source. MIT. Always free. The hosted parts are paid.

What Build does

From idea to tickets before any code

Agents turn an idea into a spec, a plan and small tickets. Every step leaves a record: the ticket, the decision record, the review and the pull request. A person signs off where your team chooses. By default, that is the merge.

Reviewers sized to the change

The reviewers depend on the size of the change. A person approves the merge at every size.

  • Lean Docs, comments and config text. Rex, the review agent, gives a quick review.
  • Standard Ordinary code changes. Rex gives one full review.
  • Heavy Auth, secrets, migrations, designs and large changes. Rex reviews. Security and architecture reviews also run when the changed paths match.

Adopt what you have, or start new

Hand over a repository you already have:

  1. Run /handover with a project name and the path or URL of the repository.
  2. It clones the repository into the workspace folder of your ops repository.
  3. It reads the code, finds the stack and scores how ready the code is for agents, in five areas.
  4. It writes a handover assessment: the current state, the risks and a plan.
  5. You choose the documents to make, such as architecture diagrams and an AGENTS.md file.
  6. It adds the project to your registry and offers to file the next steps as tickets.

Or start a new product: run /scaffold. It asks a short interview and makes the project floor.

Runs on your machine

The framework and the command line run where your developers already work. The Cockpit desktop app gives the same steps to people who never open a terminal.

How it connects

Your agents read Keel, your team's rules and context, while they write.

The ticket, decision record and review your agents produce here are what the Gate checks on GitHub.
