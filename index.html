One set of rules, used twice

Before the code exists, the rules guide the agent. That is the process. After the code exists, the same rules check the pull request, and a named person approves it on GitHub. That is the gate. A miss becomes a new rule.

  1. Guide. Your agents read your tickets, plans and rules before they write code.
  2. Check. The ApexYard check runs on every pull request and lists what is missing.
  3. Approve. The merge waits until a named person approves it on GitHub.
  4. Learn. A miss becomes a new rule, so the next change starts from it.

Others tell your agents the rules. ApexYard checks they followed them, and learns from every miss.

What your team gets

The check on GitHub

Each pull request gets an ApexYard check. It shows what passed, what failed, and the next step, in the place where your team already reviews code.

Prove: the dashboard

The dashboard lists each pull request, its check result, each process step, and the person who approved the merge. The Production-Ready Score shows how close each repository is to your standard. Coming

The evidence record for each merge Coming

Each merge keeps a record: the check result, the reviewer, the named approver and the commit. You can export it for an audit.

Learn: the knowledge base your agents read Coming

Your organisation's rules, decisions and tickets in one place, with owners and versions. Agents read them over MCP. A miss becomes a new rule.

The organisation view Coming

What ApexYard can see

The GitHub App permissions

  • Pull requests: read
  • Checks: write, to post the ApexYard check
  • Metadata: read
  • Members: read, to check for an organisation admin at sign-in

The App does not ask for the Contents permission.

Where the data lives

The hosted service runs on AWS in the eu-west-1 region, in Ireland.

We keep each evidence record for 13 months, then delete it. We delete your data within 30 days when you ask.

Data processing agreement

A data processing agreement is available on request, on standard terms.

Sub-processors: Amazon Web Services, for hosting, and GitHub, for sign-in and the App.

Built in the open, so you can read every rule

The framework is open source under the MIT licence. The rules, hooks, skills and review agents are plain files in your repositories.

66 hooks and 22 rules ship in release v5.10.0. The framework has stars on GitHub.

Install with one command, or use the Cockpit when it ships. Prefer to fork? Follow the fork steps in the docs.

Install the CLI with one of these commands.

curl -fsSL https://apexyard.ai/install | sh
brew install me2resh/tap/apexyard
npx create-apexyard

Then run apexyard init in your project folder, open your agent tool, and run /setup.

cd your-project
apexyard init
/setup

The Cockpit, the ApexYard desktop app, is coming. It will run the same apexyard init and /setup steps for you.
