The rules get stronger with every merge

You keep one rule set, not a style guide in one place and a review checklist in another. The rule that steers the agent is the rule that blocks the merge.

  1. Guide. Agents start from your tickets, plans and handbooks, not from a blank prompt.
  2. Check. A missing test, plan or review shows up with the exact fix.
  3. Approve. An agent can never sign off its own work.
  4. Learn. A review finding becomes a rule in one step, so the same mistake cannot merge twice.

Others tell your agents the rules. ApexYard checks they followed them.

What ApexYard can see

The GitHub App permissions

  • Pull requests: read
  • Checks: write, to post the ApexYard check
  • Metadata: read
  • Members: read, to confirm who can manage your organisation

Install with one command. Prefer to fork? Follow the fork steps in the docs.

Install the CLI with one of these commands.

curl -fsSL https://apexyard.ai/install | sh
brew install me2resh/tap/apexyard
npx create-apexyard

Then run apexyard init in your project folder, open your agent tool, and run /setup.

cd your-project
apexyard init
/setup

The desktop app is on its way. It will run apexyard init and /setup for you. Use the terminal until then.
