What the GitHub App can see

The App cannot open the files in your repository: it has no Contents permission. From each pull request it takes only the names of the changed files, never the code.

  • Pull requests: read. Titles, descriptions, reviews and the list of changed files.
  • Checks: write. To post the ApexYard check on each pull request.
  • Metadata: read. Repository names, and who can write to each repository.
  • Members: read. To confirm who can manage your organisation when you sign in.

The check blocks a merge only when you make it required in GitHub. You can remove the App at any time.

One process, three places

Build puts your agents through tickets, plans and reviews. The Gate checks that process on every pull request. Readiness checks the whole repository before you ship.

  1. BuildYour agents work as an engineering team, from the first idea to reviewed code.
  2. GateThe check your reviewers see in each pull request.
  3. ReadinessKnow what is safe to ship, area by area.

Install free. Read every rule.

MIT licensed. Every rule, hook and review agent is a plain file you can read, change or remove.

66 hooks guard each edit, commit and push on the developer's machine. developers have starred the framework on GitHub.

Prefer to fork? Follow the fork steps in the docs.

Install the CLI with one of these commands.

curl -fsSL https://apexyard.ai/install | sh
brew install me2resh/tap/apexyard
npx create-apexyard

Then run apexyard init in your project folder, open your agent tool, and run /setup.

cd your-project
apexyard init
/setup
