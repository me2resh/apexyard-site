> Generated by apexyard `/handover` on 2026-09-18 — review and refine. Keep this file focused on stable operating info (commands, layout, conventions). It is the operating manual for any agent (Claude Code, Cursor, Codex, …) working in this repo.

## What this is

Public ApexYard marketing and docs site. Hand-authored static HTML, Markdown alternates, and `llms.txt`. There is no application server and no root build step.

## Tech stack

- Language / runtime: HTML, CSS, vanilla JavaScript. No TypeScript. Node is used only to render OG cards (`og/render.js` + Playwright). `og/package.json` is gitignored.
- Framework: none
- Database: none
- Test framework: bash suites under `.github/tests/`
- Hosting: Netlify (`netlify.toml`) and AWS S3 + CloudFront (OIDC deploy workflows)

## Commands

## Project layout

- `*.html` — public pages (`index`, `architecture`, `skills`, `how-it-works`, `game`, `404`)
- `*.md.gen` — markdown alternates served as `/foo.md`
- `llms.txt`, `llms-full.txt`, `skill.md` — agent-facing manifests
- `netlify.toml`, `_headers`, `_redirects` — Netlify CSP, MIME types, rewrites
- `.github/workflows/` — link-check, shell-tests, AWS staging and production deploy
- `.github/scripts/` — count derivation, count verify, CloudFront invalidation
- `og/` — committed OG PNGs plus Playwright render helpers
- `apexdock/` — ApexDock download and onboarding pages

## Conventions

- Harnessability is **low**. There is no TypeScript strict mode, no ESLint, and no coverage threshold.
- Keep Rex architecture handbooks **advisory**. Blocking clean-architecture or Next.js rules will false-positive on this tree.
- Treat HTML, `.md.gen`, `llms.txt`, and `skill.md` as one content set. Primitive counts must stay in sync. Use `derive-counts.sh` and `verify-counts.sh`. Do not hand-edit one surface.
- Shell scripts are the linted code. Run `shellcheck` before changing `.github/scripts/` or `og/render.sh`.
- Do not add `nextjs-ci.yml` unless the site is rewritten in Next.js.

## Gotchas

- Dual publish path: Netlify git deploy and AWS S3/CloudFront both exist. Confirm which host answers https://apexyard.ai before changing deploy.
- `main` has no GitHub branch protection. Do not push directly to `main`. Open a PR.
- CSP in `netlify.toml` allows `'unsafe-inline'` for script and style. That is required for inline CSS, gtag, and animation JS.
- No coverage threshold. Shell tests passing does not mean HTML/JS is covered.
- `og/package.json` is gitignored. OG render dependencies are throwaway.
- Production AWS deploy waits on the GitHub `production` environment. Staging deploys from `staging` via `deploy-aws-staging.yml`.
